   - Pure sink: consumes (tick, event, payload) tuples; never returns state to the

     driven by cue priority; steal executes stop+reuse exactly like spike 04.
   - Music state machine (minimal): states from music.json; transitions quantized to
     the next bar boundary using the spike 05 schedule-ahead pattern (fade_start both
     stems + stop_time on the outgoing; scheduled >= one tick ahead, never adjusted).
   - Ducking: schedule-ahead GROUP fades only (attack fade down at cue frame, release
     fade up at cue-end estimate or fixed hold from data). No callbacks, no polling
     hacks; end-of-sound remains polled in update().
3. COMMAND RECORDER (the bit-exact log): a thin recorder layer that AudioSystem calls
   INSTEAD of GTA::Native directly; it forwards to FFI and, when recording, appends
   one line per command: frame, mechanical handle id (sound_007, bus_music), op,
   args - floats serialized as BOTH %.9g (human) and IEEE-754 hex bits (the bit-exact
   md5 rides the hex, never decimal strings). Same code path drives FFI and log so
   the log cannot lie.
   - PRODUCTION MODE (recorder nil): zero per-tick Ruby allocations on the
     steady-state path - prove with a spike-03-style scaling test (1k vs 5k ticks,

     RECORDER-EQUIVALENCE TEST: same replay with recorder on vs off must render

LAWS THAT BITE IN M2 (restated because this milestone tempts each one):
- The audio thread never enters Ruby; ducking and transitions are schedule-ahead
  fades ONLY; end-of-sound is polled. If a feature seems to need a callback, the
  feature is designed wrong - redesign, don't work around.
- Audio is a pure event sink: nothing flows back into sim/replay/netplay state.
- Zero per-tick allocations applies to the PRODUCTION path (recorder off). The
  recorder exists so the gate never pressures the hot path into logging.
- Data-driven: every new number introduced this session (duck dB, attack/release,
  tick_frames, bar lengths, file refs) lands in data/audio/*.json, not in code.
- Placeholder mechanical names only; generated tones only; no third-party audio.
- The 0.5 ms p95 command-batch bound is audio's budget; 16.6 ms belongs to game-two.
- DLL rebuild law: symbols verified in the pinned header first, VERSION bumped,
